# Нагрузочное тестирование

Сценарии на [Locust](https://locust.io): виртуальные пользователи ходят через nginx стенда так же, как браузер, — с
теми же запросами, что делает интерфейс. Итоги и сравнение «до и после оптимизации» — [`results/SUMMARY.md`](results/SUMMARY.md)
и раздел 3.5 документации.

## Роли

| Роль | Доля | Что делает |
|---|---|---|
| `Visitor` | 25% | главная страница: SPA, бандл, статистика, методика, справочники |
| `Candidate` | 33% | кабинет: сводка, уведомления, профиль, резюме, приглашения, вакансии с оценкой совпадения |
| `TestTaker` | 25% | проходит тест: полный адаптивный (если уровень доступен) или экспресс; пауза на ответ — 3–10 секунд |
| `Employer` | 17% | подборки, поиск по банку с фильтрами, карточки кандидатов, новая подборка по тексту потребности |

Учётные записи — демо-данные: 700 синтетических кандидатов (`cand000…cand699@synthetic.example`) и 5 компаний,
пароль `demo12345`. Каждый виртуальный кандидат входит под своей записью, «сотрудники» одной компании делят её токен:
лимит входа — 8 попыток за 5 минут на адрес.

## Сценарии

| Сценарий | Нагрузка |
|---|---|
| `smoke` | 20 пользователей всех ролей, 1 минута — проверка сценариев |
| `load` | 300 одновременных пользователей всех ролей, 5 минут |
| `exam` | «день тестирования»: 300 кандидатов одновременно проходят тест, 6 минут |
| `steps` | +100 пользователей каждые 90 секунд до 800 — поиск предела (`STEP_USERS`, `STEP_SECONDS`, `MAX_USERS` переопределяются переменными окружения) |

**Клиент — как браузер.** Заголовки и небольшое тело запроса отправляются одной записью в сокет, как это делает
Chromium. Обычный клиент `requests` пишет их двумя вызовами, и проброс портов Docker Desktop задерживает второй
сегмент до подтверждения первого (алгоритм Нейгла и отложенный ACK): к каждому POST добавлялось ≈ 42 мс, которых нет
ни у браузера, ни на Linux-сервере. Замер: пустой POST — 44 мс из `requests`, 3,5 мс из `curl`.

## Запуск

Тест создаёт подборки, сессии тестов и записи журнала, поэтому запускайте его на отдельной копии стенда с чистыми
данными, а не на демо-стенде:

```bash
pip install -r loadtest/requirements.txt
docker compose stop                                  # демо-стенд (данные сохранятся)
docker compose -p fsp-load up -d --build             # копия стенда со своими томами и чистыми данными
python loadtest/run.py load --label after            # сценарий: smoke | load | exam | steps
python loadtest/report.py                            # results/SUMMARY.md и docs/figures/load.png
docker compose -p fsp-load down -v && docker compose start
```

**«До оптимизации»** — тот же клиент и те же сценарии на коде коммита без исправлений: рабочая копия
`git worktree add --detach ../fsp-before <коммит>` и стенд `docker compose -p fsp-before -f ../fsp-before/docker-compose.yml up -d --build`,
прогоны с меткой `--label before`.

`run.py` запускает Locust без интерфейса и каждые 3 секунды записывает CPU и память контейнеров (`docker stats`);
результаты — `results/<сценарий>[-метка]/`: CSV и HTML-отчёт Locust, `docker.csv`, `summary.json` (в git хранятся сводка и CSV, HTML-отчёт и сырая история — только локально). Интерактивный режим
с графиками в браузере: `locust -f loadtest/locustfile.py -H http://localhost:8080`.
