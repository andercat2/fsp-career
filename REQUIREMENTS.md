# Требования к решению и их выполнение

Специальный трек ФСП хакатона «Лидеры цифровой трансформации — 2026»: платформа подбора ИТ-специалистов с обратной
механикой. Ниже — что требуется сдать, функциональные и нефункциональные требования задания (включая разъяснения
постановщиков) и где каждое из них реализовано. Подробности — в [сопроводительной документации](docs/fsp-career-documentation.pdf),
раздел 1.3.

## Функциональные требования

### Кандидат

| Требование | Как выполнено | Где посмотреть |
|---|---|---|
| Регистрация по e-mail с подтверждением | Код из 6 цифр, хранится как HMAC, действует 30 минут, 5 попыток; письма через SMTP (на стенде — Mailpit) | `/register`; раздел 9.2 |
| Профиль: форма или PDF-резюме с автораспознаванием (ФИО, контакты, стек, грейд, роли, стаж, софт-скиллы); стандартизированный PDF-профиль | Разбор вёрстки PDF по координатам строк — в том числе двухколоночного экспорта hh.ru; NER Natasha; онтология из 105 навыков; генерация PDF (ReportLab) | Кабинет → «Профиль и резюме»; раздел 5.10 |
| Категоризация по обязательному пути: опрос, выбор грейда, тест | Опрос (ИТ-направление и специализация — так постановщики уточнили «отрасль»), выбор уровня с подсказкой по резюме, адаптивный тест; категория = специализация × грейд | «Опрос и тест», «Категория и грейд»; раздел 4 |
| Тестирование, устойчивое к распространению заданий, с сопоставимой сложностью | 359 семейств заданий с уникальными вариантами, общая шкала IRT, адаптивный выбор с контролем экспозиции, три детектора нечестности, прокторинг | Разделы 4.2–4.8; страница «Методика» |
| Грейд не понижается принудительно; тест уровнем ниже и выше; ограничение частоты | Не подтвердил — грейд ниже по тому же тесту или тест уровнем ниже сразу; уверенно подтвердил — тест уровнем выше без ожидания по готовности кандидата; смена грейда и повтор уровня — не чаще раза в месяц | Раздел 4.5 |
| Неподтверждённый грейд — показывать со статусом и ниже в выдаче, не скрывать (рекомендация постановщиков) | Статус «не подтверждён»: кандидат в подборках ниже подтверждённых, ранжируется по измеренной тестом θ; показ отключается в настройках приватности | Разделы 5.1, 6.4 |
| Категория и грейд: текущий статус, история опросов и тестов | По каждому резюме: категория, θ, процентиль, ограничения; история тестов с отметками о нарушениях, смен грейда и опросов | «Категория и грейд» |
| Несколько специализаций | До трёх резюме под разные специализации, у каждого свой опрос, тест и категория | Раздел 2.2 |
| Приглашения и решения по ним | Предложение с вилкой, компанией и способом связи; принять (контакты открываются обеим сторонам), отклонить с причиной, пожаловаться | «Приглашения»; раздел 2.3 |
| Регулярные короткие задания от работодателей | Раз в 7 дней задание категории; задачи с кодом проверяются тестами работодателя в песочнице, открытые ответы оценивает работодатель | «Задания»; разделы 5.8, 5.9 |
| Настройки: приватность, согласия, ФСП ID | Что видит работодатель, журнал и отзыв согласий, привязка ФСП ID | «Настройки и ФСП ID» |

### Работодатель

| Требование | Как выполнено | Где посмотреть |
|---|---|---|
| Профиль компании, потребность, подборка с обоснованием | NLP-разбор потребности, рекомендованные категории с аналитикой рынка, причины «за» и «против» у каждого кандидата | «Потребности», «Подборки»; раздел 5 |
| Поиск по банку с фильтрами: специализация, грейд, стек, ФСП | `GET /employer/candidates` и фильтры подборки | «Банк кандидатов» |
| Уточнение запроса без потери подборки | Подборка сохраняется, фильтры применяются поверх сохранённого результата | Раздел 5.7 |
| Выход на контакт по инициативе работодателя | Приглашение с вилкой, описанием и способом связи, без обязательной привязки к вакансии | «Приглашения»; раздел 2.3 |
| Вилка «от–до» обязательна в вакансии и приглашении | Валидация схем API: обе границы обязательны, «от» не больше «до»; все суммы — до вычета НДФЛ и так подписаны | Разделы 5.2, 8 |
| Статусы приглашений и откликов видны обеим сторонам | Отправлено → просмотрено → принято / отклонено / истекло / отозвано | Раздел 2.3 |
| Ограничение доступа к данным кандидата | Проверка роли и владельца на каждом эндпоинте; контакты — только после принятия приглашения или отклика | Разделы 2.4, 9 |

### ФСП

| Требование | Как выполнено | Где посмотреть |
|---|---|---|
| Связь профиля с ФСП ID, совместимость с Keycloak | OpenID Connect (authorization code + PKCE), пути `/realms/<realm>/protocol/openid-connect/*`, проверка id_token по JWKS | Раздел 7 |
| Достижения ФСП — в ранжировании внутри категории, не в грейде (разъяснение постановщиков) | Учитываются результативность и число соревнований; дисциплины равнозначны | Раздел 5.5 |
| Корректная обработка отсутствия истории ФСП | Сигнал ФСП = 0 без штрафа, явная пометка в объяснении, равный доступ к подбору | Разделы 5.5, 7.4 |

### Дополнительно и по разъяснениям постановщиков

| Требование | Как выполнено | Где посмотреть |
|---|---|---|
| Песочница с исполнением кода, антиплагиат, защита от подсказок LLM | Контейнер без сети с лимитами, открытые и скрытые тесты, антиплагиат по структуре кода, сигналы редактора | Разделы 5.9, 6.6 |
| LLM: описать, какие модели, как и зачем | LLM только для подготовки банка: черновики вопросов (локальная Qwen3-14B через Ollama или любой OpenAI-совместимый API), эксперт принимает, правит или отклоняет, принятые проходят пилотную калибровку; в тестировании и подборе LLM не участвует, персональных данных не получает | Админка → «Черновики от LLM»; разделы 4.10, 10.1 |
| ML и NLP | IRT и адаптивное тестирование, NLP вакансий и резюме, TF-IDF-близость | Разделы 4, 5, 10.1 |
| Вакансии и отклики | Публикация, редактирование, закрытие; отклики со статусами и оценкой совпадения | Кабинеты обеих ролей |
| Защита от фиктивных вакансий, интеграция с ATS | Лимит приглашений, индекс доверия компании, жалобы, скрытие предложений ниже ожиданий; webhook в ATS | Разделы 9.3, 9.4 |
| Проверка подбора на тестовом наборе пар «вакансия — кандидат» (критерий оценки) | Стенд `/evaluate` и `POST /eval/dataset`: свой набор в JSON или CSV, выдача и P@10, nDCG@10, MRR рядом с поиском по ключевым словам; встроенный пример из валидации | Раздел 6.4 |
| Быстрая проверка механики | Демо-кандидат без регистрации и экспресс-тест: 8 заданий, ≈ 7 минут, вероятности грейдов | Главная → «Без регистрации»; раздел 4.9 |

## Нефункциональные требования

| Требование | Как выполнено |
|---|---|
| OpenAPI | 105 методов с описаниями, схемами, кодами ошибок и примерами (`/docs`) |
| Docker | 6 контейнеров одной командой, ≈ 3 ГБ RAM; песочница без сети |
| 152-ФЗ | Согласия с журналом, минимизация данных до контакта, выгрузка и удаление, аудит доступа к контактам |
| Безопасность | Argon2id, HMAC-коды, JWT, ограничение частоты попыток, права по ролям, изоляция исполнения кода |
| Адаптивная вёрстка | Мобильное меню и адаптивные сетки на всех страницах |
| Качество | 525 автотестов; воспроизводимая валидация (`python -m validation.run_all`) |
| Нагрузка | Нагрузочное тестирование на Locust (`loadtest/`): 800 одновременных пользователей без ошибок на одной машине; 300 пользователей всех ролей — 110,1 запр/с, p95 50 мс (раздел 3.5 документации) |
| Собственная процедура валидации | Monte-Carlo-симуляция с известной истиной, базовые линии, абляции — раздел 6 |
